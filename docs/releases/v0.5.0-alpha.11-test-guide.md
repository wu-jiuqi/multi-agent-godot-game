## Penpot UI 流程检查

- 输入阶段至少绑定一份 brief、PRD 或 GDD，并记录产品标题、slogan 或待人工决定项。
- 产品身份阶段记录 `product_name`、`product_title`、`slogan` 和视觉方向要求。
- UX 阶段：PRD 已有流程时记录 `inherited_from_prd` 或 `authoring_skipped`；没有时只补齐缺失流程并记录人工判断。
- Penpot 阶段记录 `file_id`、Penpot file/page/shape URL、视觉系统页面或节点和交接证据。
- 本地来源必须绑定仓库内 snapshot 与 SHA-256；远程来源必须标记 provenance。
- 使用 `--ui-penpot-only` 时，不应要求 Godot Theme、场景或目标构建证据；如果进入 Godot 阶段，再按 UI Visual Contract、输入交互和构建证据执行完整验收。

示例检查入口：

```powershell
python game/game-production-pipeline/scripts/validate_art_direction_contract.py <ui-contract.yaml> --ui-penpot-only
```

## 迁移检查

从 alpha.10 项目执行 dry-run，确认 `outcome` 为 `migration_ready`、迁移器为 `migrations/0-5-0-alpha-10__0-5-0-alpha-11.py`，并审阅全部 actions、摘要和审批要求。应用后确认 `validate_plugin_lock.py`、`validate_project_instance.py` 和重复规划通过；故意提供未知 alpha.10 framework digest 时应保持 `migration_blocked`。

迁移必须保留 managed block 和 `plugin-lock.yaml`，不能手工改锁文件绕过审批。

## 编码和安装

源码和 ZIP 内文本必须为 UTF-8 无 BOM、LF。Windows PowerShell 5.1 读取中文文件时使用：

```powershell
Get-Content -LiteralPath "文件路径" -Encoding UTF8
chcp 65001
```

PowerShell 7 可用于复核。更新 Personal Marketplace 源后确认 `codex plugin list` 为 `0.5.0-alpha.11`、`installed, enabled`；独立 UI Skill 需单独解包。

```powershell
codex plugin add game-production-pipeline@personal
codex plugin list
```
