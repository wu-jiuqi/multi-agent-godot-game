## 六部门与 P2P 咨询检查

- 固定六个能力槽位存在，但没有被项目实例自动激活。
- 未激活槽位的 spawn/call 必须拒绝且不产生调用记录。
- 部门经理只能在授权范围内响应；QA 不能为被测域写入受保护事实。
- 咨询事件必须绑定项目、组织快照、参与者和直接 peer 链；相同 mutation 的完全重复事件幂等，改变 payload 的重复 mutation 必须拒绝。
- P2P 咨询可以产生建议、冲突和待办，但不能直接写入产品事实、PRD/GDD 或审批结果；项目经理负责汇总，人类负责最终审批。

## 产品经理与 Penpot 交接检查

- 产品方向、标题、slogan 和 Prototype Intent 必须有来源和方向摘要。
- Penpot 操作必须有工具注册、能力范围、输入摘要、read-before-write、read-after-write 和稳定 Screen/Flow 映射证据。
- 人类审批必须由外部不可变记录绑定 subject digest；只填写 `status=approved` 不算批准。
- 交接校验器只接受具体项目实例，不直接接受带占位符的插件模板；`implementation_ready` 不能代表真实 Penpot 已验证、Godot 已实现或可发布。
- 当前环境若无连接 Penpot MCP，V3 应报告 `blocked`，不得伪造远程成功。

## Synthetic 故障用例

运行 `run_organization_prototype_validation.py` 后，至少检查以下结果：

- F01：未激活槽位不会被调用；
- F06：跨域 QA 写入被拒绝，受保护事实摘要不变；
- F11：Penpot 写入响应超时后通过 read-back 确认已提交，重试不产生重复节点；
- F12：断连或只读模式拒绝写入且摘要不变；
- F13：重复同步复用稳定 Screen ID，revision 不增长。

## 迁移检查

从 alpha.11 项目执行 dry-run，确认 `outcome` 为 `migration_ready`、迁移器为 `migrations/0-5-0-alpha-11__0-5-0-alpha-12.py`，并审阅全部 actions、摘要和审批要求。应用后确认 `validate_plugin_lock.py`、`validate_project_instance.py` 和重复规划通过；故意提供未知 alpha.11 framework digest 时应保持 `migration_blocked`。

迁移必须保留 managed block 和 `plugin-lock.yaml`，不能手工改锁文件绕过审批。

## 编码和安装

源码和 ZIP 内文本必须为 UTF-8 无 BOM、LF。Windows PowerShell 5.1 读取中文文件时使用：

```powershell
Get-Content -LiteralPath "文件路径" -Encoding UTF8
chcp 65001
```

PowerShell 7 可用于复核；不要依赖控制台代码页猜测 UTF-8。独立 UI Skill ZIP 需单独解包并回读 `references/penpot-handoff.md`。

更新 Personal Marketplace 源后执行 `codex plugin add game-production-pipeline@personal`，确认 `codex plugin list` 为 `0.5.0-alpha.12`、`installed, enabled`；安装后新建 Codex 会话使 Skill 生效。
