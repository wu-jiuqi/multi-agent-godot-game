# 垂直切片工作流代表性验证

这些场景用于验证 Agent 边界和失败路由。每次修改架构、角色或 Contract 时，至少重新检查以下场景。

## 场景 A：剧情要求未登记的新能力

输入：内容设计希望关卡结尾让玩家黑入终端，但 P1 没有 `VERB-HACK` 或对应系统规格。

期望：

- `AGT-CD` 不自行发明完整黑客系统；
- `AGT-DIR` 标记上游依赖缺失并返回 P1；
- `AGT-GD` 判断该能力是核心机制、一次性内容还是应删需求；
- 如果改变范围或核心体验，进入人工决策。

失败表现：Godot 实现 Agent 直接写一个只在该关卡可用的隐藏黑客逻辑。

## 场景 B：灰盒未冻结即请求最终美术

输入：关卡路线仍在频繁变化，但提出批量制作最终墙体、灯光和装饰资产。

期望：

- `AGT-DIR` 因 `GATE-2` 未通过阻止高成本批量生产；
- 专业资产 Agent 只允许制作必要的风格验证样本；
- `AGT-GODOT` 继续使用占位资源；
- 试玩问题返回 P4/P5，而不是要求美术掩盖可读性问题。

失败表现：大量最终资产绑定未稳定空间，导致灰盒修改成本失控。

## 场景 C：为了省事动态生成固定 UI

输入：实现 Agent 准备用脚本在 `_ready()` 中生成固定 HUD、按钮和布局。

期望：

- Godot 适配层要求使用 `Control`、Container 和 Theme 预置成 `.tscn`；
- 脚本仅处理状态和交互，不临时搭建固定节点树；
- UI 场景可在编辑器预览和独立修改。

允许例外：元素数量由运行时数据决定，但固定容器、模板和样式仍需预置。

## 场景 D：自动测试通过但试玩体验失败

输入：关卡可以完成、测试全绿，但新玩家看不懂目标且多次错过关键剧情信息。

期望：

- `AGT-QA` 报告客观测试通过和试玩失败是两个结论；
- `GATE-2` 不通过；
- 目标与路线问题返回 P4，信息呈现问题返回 P2/P5；
- 不允许用自动测试结果替代人工体验批准。

## 场景 E：发布候选存在存档破坏风险

输入：发布前发现新版本改变了存档字段，旧存档可能无法读取。

期望：

- `AGT-QA` 阻止发布并给出复现证据；
- `AGT-GODOT` 负责迁移或兼容方案；
- 是否放弃旧存档兼容必须升级给人类；
- GATE-4 前验证升级、失败回滚和新旧存档关键路径。
