# 《心界 Mindrift》项目配置

**仅当用户明确要求为当前《心界》或 Mindrift 项目制作资产、遵循其现行设定时读取和应用。** 本文件不是通用厚涂风格的题材限制。仅要求“类似心界的笔触”时，使用通用风格规范，不自动引入剧情或项目禁用意象。

## 来源与优先级

本配置提炼自项目以下两份标注更新日期为 **2026-07-29** 的文档：

- `docs/隐喻与互动视觉设计.md`：目标视觉与交互规范，明确取代旧《神谕动画视觉设计》。
- `docs/心界_策划案.md`：当前叙事与产品设计基线，说明仓库内部分场景、脚本和章节资源仍来自旧原型。

以上路径相对于 Mindrift 项目根目录，不是本 Skill 仓库内的文件。它们与历史 `art_review/`、旧提示词或旧原型冲突时，以这两份现行基线为准；若用户提供经确认的新基线，则使用新版本并明确差异。不要因历史图片已存在于仓库就视为当前授权风格依据。

本仓库不附带原项目文档和游戏图片。没有项目文件访问权时，可使用本摘要完成常规视觉请求；涉及摘要未覆盖的剧情事实时，不推断或补写设定。

## 视觉基线

- 2D 固定场景，厚涂油画与粗画布；通用材质方法见 [style-bible.md](style-bible.md)。
- 日常空间首先可信，保留陶壁、旧纸、木材、布料和现实电子屏幕的材质差异。
- 默认使用奶油白、灰粉、旧黄、暗酒红、深蓝与城市夜色；这是色彩家族，不是经过取样的精确 HEX 色卡。
- 日常阶段以现实为主，荒诞只在边缘出现。空间变形、重复物件、局部颜色越界等，应服务已明确的人物认知或行动后果。
- 神话通过构图、色彩、声音与物件关系形成共鸣，不向玩家发布命令，不成为统一谜题或收集系统。
- 不把所有日常场景画成迫近危险；温柔、照料、可呼吸的空间也属于项目基线。

## 界面与引擎交付

- 可交互内容和主要物件必须在油画笔触中保持可辨识度。
- 需要叠加对白、按钮或说明时，在指定区域预留足够的低细节空间。
- Godot UI 文字由字体节点清晰渲染；背景图和按钮底图不烘焙可读 UI 文字。用户要概念示意图时须区分示意与正式资产。
- 文本纠正需要的浅色底字、刮擦痕迹等属于界面表现，可生成无字材质底层；具体旧文案与新文案由界面节点承载。
- 输出图片不等于已完成 Godot 导入、交互区域设置或场景验收，不在生图结果中声称这些工作已完成。

## 当前项目中的禁止项

这些限制只服务现行项目设计，不扩展为通用生图禁令：

- 神明立绘、神名标题、神谕发动提示；统一圆环谜题、烙印结算和苦难资源。
- 用红色、羊角或项圈直接宣布南星是反派；这不等于禁止画面使用红色。
- 现实裸照、可辨认人体缩略图或猎奇特写；私密影像占位只使用不含人体轮廓的模糊色块或纯文本界面条目。
- 用血腥、精神病院或受害者失控作为“高潮美术”。
- 结局星级、颜色等级、善恶条、最佳路线光效；三条路线在视觉表达上不排道德高低。

不要从旧提示词自动恢复固定悲剧、神谕、苦难采集或相关视觉系统。遇到明确要求恢复旧系统、且与当前项目基线冲突的请求时，先指出具体冲突并确认这是局部例外还是项目基线更新；不要悄悄把旧设定当成现行规范。
