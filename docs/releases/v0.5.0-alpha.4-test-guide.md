# v0.5.0-alpha.4 测试与发布验收手册

## 全量回归与构建

```powershell
python -m unittest discover -s game/game-production-pipeline/tests -p 'test_*.py' -v
python game/game-production-pipeline/scripts/validate_text_encoding.py --plugin-root game/game-production-pipeline
python -m compileall -q game/game-production-pipeline/scripts game/game-production-pipeline/migrations
python game/game-production-pipeline/scripts/build_release.py --plugin-root game/game-production-pipeline --output-dir dist

python -m unittest discover -s skills/ui-ux-pro-max/scripts/tests -p 'test_*.py'
python scripts/build_ui_ux_release.py
git diff --check
```

构建报告必须为 `state=built`、`source_line_endings=LF`，并包含 framework digest 与 ZIP SHA-256；重复构建以及 `core.autocrlf=true/false` 导出必须得到相同字节。

## 真实形状迁移回归

测试夹具包含六个已批准 Agent Preset、六个旧生成器 Adapter、三个旧插件 Skill 摘要、一个项目来源 Skill，以及现有独立 Skill Binding 审批。dry-run 必须同时出现：

- 三个插件 Skill 的 `before_digest` / `after_digest`；
- 新的 64 位 Skill Binding `subject_digest` 和独立审批记录路径；
- 六个 Adapter `update`；
- `AGENTS.md` 与最后提交的 `game-pipeline/plugin-lock.yaml`。

缺少 `--binding-approval-digest`、摘要错误或缺少批准者时，项目和备份目录必须零写入。使用正确的两份批准应用后，项目校验必须为 `normal`，六个 Adapter 的 `generator-version` 必须为 `0.5.0-alpha.4`，重复规划必须为 `no_change`。

## 故障与所有权注入

- 把任一目标 Adapter 改成无 managed marker 的用户文件，dry-run 必须 `migration_blocked`，且不覆盖文件。
- 强制后置项目校验失败，执行器必须恢复 Skill Binding、六个 Adapter、managed block、lock，并删除本次创建的两份审批记录；备份清单标记为 `auto_rolled_back`。
- 项目来源 Skill 的路径与摘要迁移前后必须一致。
- 未知旧 framework digest、损坏 managed block 和计划后文件漂移继续 fail closed。

## 手工 dry-run

```powershell
$plan = python game/game-production-pipeline/scripts/migrate_plugin.py `
  --project-root <project> | ConvertFrom-Json

$plan.outcome
$plan.skill_binding_changes
$plan.skill_binding_approval
$plan.agent_adapter_actions
$plan.plan_digest
```

仅当 `migration_ready` 且项目所有者批准迁移计划摘要后执行；若 `skill_binding_approval.required=true`，还需独立批准新的 Skill Binding 摘要：

```powershell
python game/game-production-pipeline/scripts/migrate_plugin.py `
  --project-root <project> `
  --migration-at $plan.migration_at `
  --apply `
  --approval-digest $plan.plan_digest `
  --approved-by human:owner `
  --binding-approval-digest $plan.skill_binding_approval.subject_digest `
  --binding-approved-by human:owner
```

仅当 `skill_binding_approval.required=true` 时传入最后两个绑定批准参数。

禁止只把 `plugin-lock.yaml` 改回旧版本；回退必须使用 `game-pipeline/.cache/migrations/<plan_digest>/` 的逐字节备份。


预期插件为 `installed, enabled`。Windows PowerShell 5.1 即使执行 `chcp 65001` 也必须显式指定 UTF-8；PowerShell 7 可用于复核。不要手工编辑 managed block 或 `plugin-lock.yaml`。

## alpha.3 到 alpha.4 的新增验收

- 已发行 alpha.3 摘要 `9d1e7797b7dad799317dc9bc1b710f05018bf9fe6ce144fbcb32e17ae4ad3562` 可迁移；未知摘要必须阻断，不能将开发快照当作发行版本。
- 空团队实例仅规划 AGENTS.md 与 plugin lock；已批准团队的六个托管 Adapter 更新生成器版本。
- 插件 Skill 内容没有变化且原审批有效时，绑定文件和原审批逐字节保留，不要求新的绑定审批。
- 迁移后项目校验 normal，重复规划 no_change；显式回退完整恢复原文件。
- 旧 alpha.3 迁移入口仍只接受 alpha.3 目标；调用它处理 alpha.4 安装必须阻断，不能因复用函数而放宽历史版本约束。

## 独立 Skill 与附件复现

插件 ZIP 必须包含 gameplay-designer.md、机制工作流、模板与合成示例，且不包含 ui-ux-pro-max。独立 Skill ZIP 顶层为 ui-ux-pro-max/，需包括入口、references、数据和脚本，排除 Python 缓存。

运行两次 `python scripts/build_ui_ux_release.py`，SHA-256 必须一致；用 core.autocrlf=true/false 分别导出最终 Git 提交并重建，摘要也必须一致。上传后核对 GitHub 附件大小与 SHA-256。UI/UX 是独立附件，不能把插件安装成功当作 Skill 同步成功。

本版以角色和文档模板发布，自动校验不代替九个行为情境的实际运行、真实项目设计评审或真人试玩。发布过程不改写真实游戏项目。
