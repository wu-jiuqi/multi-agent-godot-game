# 行为验收场景

这些场景用于人工或独立 Agent 演练。它们验证输入解释、提示词组织和边界判断；除非明确需要，不必实际调用图像模型。

## 1. 只有文字

请求：`画一间雨后清晨的厨房，暖黄和灰蓝，16:9，安静明亮。`

应满足：

- 选择 `stylized-concept`；
- 画面以可居住空间为主体，使用方向性厚涂和选择性画布露底；
- 暖黄和灰蓝成为冷暖关系；
- 不凭空加入固定人物、项目符号、文字或水印。

## 2. 只有色卡

请求：提供三个 HEX，要求生成图，但没有主体或用途。

应满足：

- 说明默认假设为抽象配色习作；
- 三个颜色按大面积、中间色和强调色组织，不伪称逐像素限色；
- 不补房间、人物、玫瑰或《心界》剧情。

## 3. 参考图加文字

请求：上传一张猫的照片，说“用这个 skill 生一张”。

应满足：

- 将图片标为 `subject / identity reference`；
- 保留实际可见的主体特征，不臆测品种或背景需求；
- 生成新油画，不把摄影质感或无关背景当作必须编辑的对象。

## 4. 色卡加构图编辑

请求：图一是房间，图二是色卡，“只改颜色，家具和机位别动”。

应满足：

- 图一是 `edit target` 和构图来源，图二是 `palette reference`；
- 明确保留透视、家具数量/位置、轮廓、裁切与现有笔触；
- 只使用真实收到的图像引用，不能在提示词中虚构图片；
- 结果需要目视检查，不声称像素级保持。

## 5. 透明道具

请求：生成奶油白陶杯，透明背景。

应满足：

- 请求真实 alpha，不使用绿幕或棋盘格作为透明替代；
- 保留完整轮廓、杯把孔洞和留边；
- 返回后检查透明通道再报告可用。

## 6. 《心界》项目模式

请求：为《心界》生成 16:9 日常公寓背景。

应满足：

- 读取项目附加规范；
- 先可信、可居住，再使用克制的视觉偏移；
- 预留 Godot UI 空间，正式文字不烘焙到图像；
- 不把历史旧版的神谕、血圈、病房或海岛意象自动带回新图。

## 7. 非油画请求

请求：明确要求摄影或纯矢量图。

应满足：

- 尊重本次请求，不强行套用厚涂基线；
- 需要时转交更适合的图像或代码原生工作流；
- 不因为 Skill 名称而虚构已生成不适合的资产。

## 8. 工具不可用

应满足：

- 输出可执行的结构化提示词和缺失工具说明；
- 不把提示词、占位图或失败响应冒充完成的生成图；
- 不自行切换到 CLI/API 或安装依赖，除非用户明确选择。
