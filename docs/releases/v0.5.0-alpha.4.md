# v0.5.0-alpha.4 — 游戏机制策划与独立 UI/UX Skill

本版把游戏机制与玩法策划初稿纳入插件发布，提供机制选项、核心循环、规则规格、参数假设、风险分析和最小原型任务书。UI/UX Skill 同批提供独立附件。仍为 Alpha 预览版，不是 Production Ready。

## 交付内容

- 插件新增 `agents/gameplay-designer.md`、`workflows/gameplay-design.md`、策划包模板、研究依据、合成示例与九个行为验收情境。
- 机制策划可由游戏设计 Agent 兼任，也可按项目需要设专项岗位；同一机制只保留一个写入负责人。发布和安装不会自动新增项目岗位、审批、具名 Agent 或游戏规则。
- 独立 `ui-ux-pro-max` Skill 优化任务分流、UX 流程、状态和失败恢复、平台验收及检索指导。它位于仓库顶层 `skills/`，不在游戏管线插件 ZIP 内。
- 新增七条显式迁移入口：白名单内 `0.3.0-alpha.1`、`0.4.0-alpha.2/3/4`、`0.5.0-alpha.1/2/3` 可直接迁移到本版。
- 迁移保留 Skill Binding 独立审批与托管 Adapter 的完整事务。Skill 内容及绑定审批仍有效时保留原绑定；Adapter 按新生成器版本更新；plugin lock 最后写入。未知摘要、目标漂移和非托管文件冲突仍阻断。

## 更新方式

发布附件中的 `game-production-pipeline-v0.5.0-alpha.4.zip` 是插件；`ui-ux-pro-max-v0.5.0-alpha.4.zip` 是独立 Skill 快照，附件版本对应本仓库 Release，不表示新增 Skill 版本机制。

插件需要安装来源指向本版，再从个人 Marketplace 安装或更新；仅创建 GitHub Release 不会自动刷新本机 Marketplace 或已安装缓存：

```powershell
codex plugin add game-production-pipeline@personal
codex plugin list
```

确认实际版本为 `0.5.0-alpha.4` 且状态为 `installed, enabled`。现有项目先使用新插件执行迁移 dry-run，审阅精确 `plan_digest`；仅当 `skill_binding_approval.required=true` 时额外审阅新的 Skill Binding 摘要。不要手工覆盖 managed block 或 `plugin-lock.yaml`。详见同版测试手册。

独立 UI/UX Skill 的 ZIP 顶层为 `ui-ux-pro-max/`，部署到实际 Skill 安装目录前先比较本地自定义修改并备份。本机已经同步本批更新的用户不需要重复复制；项目内另存副本或摘要绑定时单独核查。插件升级不替代此步骤。
