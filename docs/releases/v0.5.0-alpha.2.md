# v0.5.0-alpha.2 — 可复现发布与安全迁移修复

`v0.5.0-alpha.2` 是 `alpha.1` 主美方向闭环的发布工程修复版。主美 Agent、D0–D4、风格圣经、2D/3D/UI 技术 Profile、Godot benchmark、权利溯源和 UI 视觉边界保持不变；本版修复同一 Git 提交在 LF/CRLF 环境中生成不同框架与 ZIP 摘要的问题。

## 问题与影响

`alpha.1` 发布说明记录的 LF 工作区摘要为 `1a06826e… / 4e11c80c…`，而 `core.autocrlf=true` 的 Git 导出可重建为 `56a98f18… / d3e6defb…`。两者来自同一 `dbac6b5` tag 的不同换行字节，不是主美功能丢失或串版。Bootstrap 的精确摘要门禁按设计暂停了迁移，项目实例未被写入。

## 修复内容

- 在插件根增加 `.gitattributes`，文本资源固定为 UTF-8 无 BOM + LF，常见图片、字体、DCC 和压缩包显式保持 binary。
- 文本校验器新增 `non-lf-line-ending`；源码或发布 ZIP 中任一目标文本存在 CRLF/单 CR 时构建 fail closed。
- 发布 ZIP 改用固定时间戳、路径、权限与 `ZIP_STORED`，避免不同 zlib 版本产生不同压缩字节。
- 构建报告升级为 `game-production-release-build/v2`，直接回传 `framework_digest` 和 `source_line_endings=LF`。
- 回归测试在临时 Git 仓库中分别以 `core.autocrlf=true/false` 导出同一提交，要求框架摘要和发布 ZIP SHA-256 完全一致。

## 迁移与兼容

- `v0.3.0-alpha.1`、`v0.4.0-alpha.2`、`v0.4.0-alpha.3` 和 `v0.4.0-alpha.4` 保留直接、显式、可回退的主美控制面迁移。
- `v0.5.0-alpha.1` 新增只更新 `AGENTS.md` managed block 和 `plugin-lock.yaml` 的元数据迁移，并接受已知 LF/CRLF 两种发布摘要。
- 迁移仍先 dry-run，再由项目所有者批准精确 `plan_digest`；应用前保存逐字节备份，写入审批记录，最后才更新 lock。
- 现有美术/资产 Contract、风格圣经、图片、DCC、Godot 场景、UI、组织、Snapshot 和 Event History 保持逐字节不变。禁止只把 `plugin-lock.yaml` 改回旧版本。

## 验收结论

- 全量单元测试、UTF-8/LF、compileall、静态 Contract 与 Skill quick validate 通过。
- `autocrlf=true/false` 两种 Git 导出的 framework digest 与发布 ZIP 摘要一致。
- `alpha.1` 的两种已知摘要均能生成只含受管元数据的迁移计划；未知摘要仍 fail closed。
- 本版仍是 Alpha；主美质量、真实 DCC/import 链、多人资产吞吐和独立 UI workflow 仍需项目回放。

## 安装与中文编码

```powershell
codex plugin add game-production-pipeline@personal
codex plugin list
```

预期显示 `installed, enabled`。Windows PowerShell 5.1 读取 UTF-8 无 BOM 中文时使用：

```powershell
Get-Content -LiteralPath "文件路径" -Encoding UTF8
```

`chcp 65001` 不会改变 Windows PowerShell 5.1 的文件读取默认编码；PowerShell 7 通常采用更安全的 UTF-8 默认值。不要手工覆盖 managed block 或 `plugin-lock.yaml`。
