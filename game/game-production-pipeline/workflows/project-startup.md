# 共同立项与自主生产

## 目标

项目所有者可以只带一个想法进入流程。Agent 主动研究、补足专业视角、提出有证据的选择，与所有者共同敲定项目细节；启动后按明确授权自行制作、自检、返工和独立审核。

## 顺序

1. 用 bootstrap 建立控制面；项目简报和 Production Charter 初始均为草案，预算为零，不代表获准生产。
2. 用 prepare-game-project-brief 开展多轮立项工作坊。覆盖目标体验、玩家、玩法、内容、视觉、UI、音频、技术、范围、工期、成本、团队、可访问性、本地化、权利、发布、验收和风险。每轮先给建议和取舍，再集中询问影响方向的问题。
3. 在立项权限内调用专家做咨询，必要时做范围与预算明确的小原型。咨询不创建永久岗位，也不冒充已批准的生产实例。
4. 并行准备 Project Brief、组织提案、Agent Presets、Skill/Tool Bindings、Production Charter。先联合审查全部草案，再按依赖顺序落盘审批；不会要求所有者独立完成规划后才开始。
5. 展示一份启动包及每个独立审批对象的精确摘要。一次明确的人类回复可以批准包内列明的对象，但不能把“同意简报”扩大为编制、预算或发布授权。
6. 先记录简报与 GATE-0/GATE-1/D2 的真实人类决定，应用已批准组织/绑定并生成适配器，再校验 Charter 的授权和计划预算分配。阻断未知项未解决不得启动。
7. 启动后由 operate-game-production-loop 按 Execution Plan 推进；普通技术和质量失败在预算内自动修复。GATE-2/GATE-3/D4 可在 Charter 中预先委派独立审核者。

## 交付与验收

启动包包含：目标及排除项、可观察验收标准、领域结论与来源、已解决和剩余问题、责任与工具配置、里程碑及每个计划的预算额度、写入范围、重试上限、异常处理、交付物、外部动作授权。未知项必须阻断启动，或明确排除，或附有实验、预算、停止条件和保守回退。

运行 validate_project_instance.py、validate_production_charter.py --require-launch 和 validate_production_run.py。结构合规只是前置条件；人类确认和独立判断需要真实对话/证据，不能由校验器生成。

## 启动后何时联系所有者

需要改变目标体验、扩大范围或授权、超出预算、缺少必需账号/素材、耗尽恢复路径、出现权利冲突时，提交一份集中异常包：影响、已尝试措施、推荐方案及需要的最小决定。已有授权内的专业判断由指定审核者处理，不重复索要批准。

默认自行完成可运行版本、验证证据和交付包。对外发布、付款、账号操作需要启动包中精确列明目标、额度、条件及 GATE-4；没有授权时停在可审阅发布包。按约定发送里程碑和完成通知，状态未变化时保持安静。

## 回退与边界

方向变化回到立项；组织缺口回到编制设计；普通失败回到生产者；证据或摘要失效回到相应源对象。原审批不能覆盖改后的内容。本版通过活跃的 Codex 任务推进生产，并非后台常驻调度服务；恢复时重放持久化事件，不以聊天记忆判断完成。
