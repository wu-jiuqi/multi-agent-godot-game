## A0 分阶段验收

从 `specialist-asset-contract.template.yaml` 创建临时 Contract，保留 A0 所需需求、责任、预算引用、权利可行性、protected paths 和 `demand_review`，允许 Source、Runtime、导入实测尚为空：

```powershell
python game/game-production-pipeline/scripts/evaluate_specialist_asset_gate.py `
  <project>/game-pipeline/assets/contracts/<asset>.yaml `
  --gate A0 `
  --project-root <project>
```

满足机器与评审条件时应返回 `state=pass`；只缺指定人工记录时返回 `awaiting_human`，脚本必须始终返回 `writes_performed=false`。

```powershell
  --history <project>/game-pipeline/loops/registry/<loop>/event-history.yaml `
  --record-template game/game-production-pipeline/contracts/loop-registry-record.template.yaml `
  --event game/game-production-pipeline/contracts/loop-registry-event.template.yaml `

  --state-machine game/game-production-pipeline/contracts/loop-state-machine.default.yaml `

```

A3 必须绑定六类当前摘要评审、授权、导入、目标平台性能与发布冻结记录。分别破坏资产文件 SHA、Contract subject digest、A3 acceptance record 或 Loop Contract 类型，命令都必须退出非 0。

## 项目总校验与 UI 只读回归

```powershell
$before = Get-FileHash -Algorithm SHA256 <project>/game/scenes/ui/screen-flow.tscn
python game/game-production-pipeline/scripts/validate_project_instance.py --project-root <project>
$after = Get-FileHash -Algorithm SHA256 <project>/game/scenes/ui/screen-flow.tscn
$before.Hash -eq $after.Hash
```

预期项目状态为 `normal` 且结果为 `True`。若专业资产 Registry 没有绑定 `loop_type=specialist-asset-production` 的 Contract，或 `generated_outputs` 与 `protected_paths` 重叠，项目状态必须为 `blocked`。

## 旧版项目迁移

```powershell
$plan = python game/game-production-pipeline/scripts/migrate_plugin.py `
  --project-root <project> | ConvertFrom-Json

$plan.outcome
$plan.actions
$plan.history_digests_before
$plan.plan_digest
```

只有 `outcome=migration_ready` 且项目所有者批准精确 `plan_digest` 后才能执行 `--apply`。动作仅允许创建缺失控制面 README、更新 `AGENTS.md` managed block 和最后更新 `plugin-lock.yaml`；已有 README、Asset Contract、Snapshot、Event History、游戏内容和 UI 文件摘要必须保持不变。迁移后项目总校验为 `normal`，重复规划应为 `no_change`。
