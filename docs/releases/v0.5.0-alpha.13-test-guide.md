## 产品发现、组织与桥接检查

- 无可用 brief/GDD/PRD/slogan 时，`$product-discovery` 生成 proposal/unknown 文档并保留来源、问题、Gate 状态；不能用空模板或候选文案直接进入原型。
- 组织注册请求包含稳定 ID、项目/组织快照摘要和完整证据；AGT-ORG 只生成 Change Set，人类批准与 `core.change_set_applied` Event 分开记录。
- Penpot 桥接按 `requested → acknowledged → completed` 检查 request/ack/result、摘要链、稳定 `file_id/page_id/shape_ids` 和连接证据；连接失败、超时、只读或权限缺口必须走 `BRIDGE`/`PENPOT_TOOL` 路由，不得伪造远端写入。
- synthetic 沙盒只能证明确定性状态机和失败注入，不证明真实 Penpot、浏览器账号、模型成本或 Godot 目标构建。

## 迁移检查

从 alpha12 项目隔离副本执行 alpha12→alpha13 dry-run，确认 `outcome=migration_ready`、迁移器为 `migrations/0-5-0-alpha-12__0-5-0-alpha-13.py`，并审阅全部 actions、摘要和审批要求。使用正确批准应用后，确认 `validate_plugin_lock.py`、`validate_project_instance.py` 和重复规划通过；故意提供未知 alpha12 framework digest 时应保持 `migration_blocked`。迁移必须保留 managed block 和 `plugin-lock.yaml` 的事务语义，不能手工改锁文件绕过审批。

## 编码、构建与 GitHub Release

源码和 ZIP 内文本必须为 UTF-8 无 BOM、LF。Windows PowerShell 5.1 读取中文文件时使用：

```powershell
Get-Content -LiteralPath "文件路径" -Encoding UTF8
chcp 65001
```

可使用 PowerShell 7 复核；不要依赖控制台代码页猜测 UTF-8。两份 ZIP 应各自生成并回读 `.sha256` sidecar；重复构建的摘要必须一致。GitHub Release 标题使用 `v0.5.0-alpha.13`，类型为 Pre-release，关闭 Set as latest，附件包括两个 ZIP、两个 `.sha256`、本发布说明和本测试手册。

更新 Personal Marketplace 源后执行 `codex plugin add game-production-pipeline@personal`，确认 `codex plugin list` 为 `0.5.0-alpha.13`、`installed, enabled`；安装后新建 Codex 会话使 Skill 生效。
