# v0.5.0-alpha.3 — Skill Binding 与 Agent Adapter 事务迁移修复

`v0.5.0-alpha.3` 修复 `alpha.2` 在真实项目迁移中遗漏运行时依赖闭包的问题。主美方向、风格圣经、2D/3D/UI 技术 Profile、Godot benchmark、权利溯源和可复现发布能力不变。

## 缺陷与处置

`alpha.2` 会更新插件框架与生成器版本，却没有把三个已批准插件 Skill 的新摘要和六个托管 `.codex/agents/*.toml` 纳入迁移计划。目标项目的后置总校验因此正确失败，执行器自动恢复全部文件；项目没有留下半成品。本版将这两类派生状态提升为显式迁移依赖。

## 修复内容

- dry-run 输出每个插件 Skill 的旧/新摘要、Skill Binding 的旧/新 subject digest、独立审批记录路径，以及全部 Agent Adapter 动作。
- Skill Binding subject 延续现有项目契约：对 `skill_bindings` 递归排除所有 `approval_id`，再使用排序键紧凑 JSON 计算 SHA-256。
- 非空 Skill Binding 必须有独立提案和 `subject_kind=skill-binding` 的不可变人工审批；它不再借用 Agent Preset 或迁移计划审批。
- apply 必须分别校验 `plan_digest` 和新的 Skill Binding digest；任何一个缺失或错误都在创建备份和写文件之前停止。
- Skill Binding、全部托管 Adapter、两类审批记录、managed block 与 plugin lock 进入同一逐字节备份事务；lock 仍是最后提交点。
- 非托管 Adapter 直接报告冲突；项目来源 Skill 不改摘要；后置校验或幂等校验失败时完整自动回退。
- 增加从白名单内 v0.3、v0.4 alpha.2/alpha.3/alpha.4、v0.5 alpha.1/alpha.2 直达本版的显式迁移器。

## 真实项目回放结论

使用自动回滚后仍锁定 `0.4.0-alpha.3` 的真实项目隔离副本完成回放：三个插件 Skill 摘要更新、六个托管 Adapter 重建、独立 Skill Binding 审批与迁移审批写入、plugin lock 最后更新；项目总校验为 `normal`，重复规划为 `no_change`。原项目未在发布准备阶段写入。

## 安装与中文编码

```powershell
codex plugin add game-production-pipeline@personal
codex plugin list
```

预期显示 `installed, enabled`。Windows PowerShell 5.1 读取 UTF-8 无 BOM 中文时使用：

```powershell
Get-Content -LiteralPath "文件路径" -Encoding UTF8
```

`chcp 65001` 不会改变 Windows PowerShell 5.1 的文件读取默认编码；PowerShell 7 通常采用更安全的 UTF-8 默认值。不要手工覆盖 managed block 或 `plugin-lock.yaml`。
