# v0.4.0-alpha.2 — v0.3 到 v0.4 的可回退项目迁移

## 版本定位

`v0.4.0-alpha.2` 是 v0.4 Alpha 阶段的迁移闭环版本。它保留 `alpha.1` 已发布的项目经理启动模式、项目简报审批边界、UTF-8 中文编码规范和 Windows PowerShell 5.1 兼容指引，并新增从已发行 `v0.3.0-alpha.1` 项目到 v0.4 的显式迁移器。

本版本仍是 Pre-release，不是 Production Ready。迁移器不会自动查找或修改游戏项目；每个项目必须单独执行 dry-run、审阅完整影响计划、批准精确摘要，再决定是否应用。

## 新增迁移能力

- 新增 `migrations/0-3-0-alpha-1__0-4-0-alpha-2.py`，只处理明确的 v0.3→v0.4 路径；
- 将原只读迁移预检升级为确定性的 `game-production-plugin-migration-plan/v2`；
- 新增 `scripts/migrate_plugin.py`，统一提供 dry-run、摘要审批执行和显式回退；
- 迁移计划绑定项目绝对路径、源/目标版本、源/目标框架摘要、迁移时间、迁移器、逐文件前后摘要与验证条件；
- 只接受已发行 v0.3 的已知 framework digest，未知开发快照或疑似损坏安装 fail closed；
- 应用前在 `game-pipeline/.cache/migrations/<plan_digest>/` 保存受影响文件的逐字节备份；
- 计划后文件发生变化、managed block 摘要损坏、目标文件冲突或审批摘要错误时，在首次项目写入前停止；
- plugin lock 始终最后更新，作为迁移完成点；
- 应用后强制要求 plugin lock、项目实例和重复迁移规划全部通过；
- 写入或验证过程中出现任何错误时自动按备份回退；
- 手工回退前再次验证迁移后文件摘要，拒绝覆盖迁移后新增的用户修改。

## 迁移范围

迁移器只处理 v0.4 必需的控制面变化：

1. 创建 blocked 状态的 `game-pipeline/project-definition/project-brief.yaml` 初始草案；
2. 创建项目文档基线说明；
3. 在 Fact Sources 中登记项目简报来源；
4. 在摘要验证通过后更新 `AGENTS.md` managed block；
5. 写入绑定迁移计划摘要的人工审批记录；
6. 最后更新 `game-pipeline/plugin-lock.yaml` 的版本、框架摘要和锁定时间。

迁移器不会修改组织快照、事件历史、Organization Change Set、Agent Preset、Skill Binding、Codex Agent TOML 或任何游戏内容。已有同名项目简报或说明只要不是迁移器生成的精确初始内容，就会作为冲突返回，不会被覆盖。

## 支持的源版本

源版本必须满足：

- 基础版本为 `0.3.0-alpha.1`，可以带 Codex Marketplace cache-buster；
- lock schema 为 `game-production-pipeline-lock/v1`；
- `plugin_id` 为 `game-production-pipeline`；
- `compatibility_mode` 为 `strict`；
- framework digest 属于 Git 标签源码、v0.3 发布 ZIP 或已部署 Marketplace 兼容构建的已知摘要白名单。

更早版本、其他 v0.3 开发快照、未知摘要和同版本摘要漂移不会被猜测迁移。

## 使用流程

先确认项目 Git 工作区干净并已有独立备份。在插件根目录执行 dry-run：

```powershell
$plan = python scripts/migrate_plugin.py `
  --project-root D:\Game\MyProject | ConvertFrom-Json

$plan.outcome
$plan.actions
$plan.plan_digest
```

只有 `outcome` 为 `migration_ready`，且项目所有者审阅全部动作后，才能复用计划中的时间和摘要执行：

```powershell
python scripts/migrate_plugin.py `
  --project-root D:\Game\MyProject `
  --migration-at $plan.migration_at `
  --apply `
  --approval-digest $plan.plan_digest `
  --approved-by human:owner
```

成功后应显示：

- `mode` 为 `applied`；
- `plugin_lock_state` 为 `normal`；
- `project_state` 为 `normal`；
- `idempotent_outcome` 为 `no_change`。

如果尚未继续编辑任何迁移目标文件，可以使用同一摘要回退：

```powershell
python scripts/migrate_plugin.py `
  --project-root D:\Game\MyProject `
  --rollback `
  --plan-digest $plan.plan_digest `
  --confirm-rollback $plan.plan_digest
```

禁止只修改 `plugin-lock.yaml`、复制 v0.4 文件伪装迁移或绕过摘要审批。

## 项目简报的迁移语义

迁移只建立 blocked 初始草案，不会从现有游戏文件中推断玩法、美术、范围或技术方向，也不会把旧项目自动判定为 staffing-ready。项目所有者仍需提供或确认项目规划，由项目经理启动工作流整理来源、事实、偏好、假设、未知项和责任需求，再批准精确 `subject_digest`。

已经存在组织和 Agent 的 v0.3 项目不会因迁移而删除编制；但后续组织设计应先补齐并批准项目简报。

## 中文编码兼容

插件源码、迁移器、模板、生成文件、备份清单和发布 ZIP 内文本继续统一使用 UTF-8 无 BOM。Windows PowerShell 5.1 的无参数 `Get-Content` 仍可能使用本地 ANSI 代码页；读取中文时使用：

```powershell
Get-Content -LiteralPath "文件路径" -Encoding UTF8
```

`chcp 65001` 只调整控制台代码页，不保证 `Get-Content` 使用 UTF-8。PowerShell 7 或明确配置为 UTF-8 的编辑器一般可以直接读取。看到乱码时先按 UTF-8 重新读取，不要覆盖 managed block、`plugin-lock.yaml` 或批量转码项目文件。

- 74 项单元测试全部通过，其中包含迁移 dry-run、错误审批摘要、三种已发行源摘要、未知源摘要、冲突文件、apply、项目完整验证、幂等、自动回退、显式回退和回退漂移保护；
- CLI 隔离验收中，bootstrap 首次写入 18 个文件、第二次写入 0 个文件，项目状态为 `normal`；
- v0.3 隔离项目的迁移计划包含 5 个受控目标，apply 后 plugin lock 与项目实例状态均为 `normal`；
- 迁移后重复规划返回 `no_change`；
- 显式回退逐字节恢复旧文件，删除迁移创建的项目简报、说明和审批记录，并使旧锁重新进入 `read_only`；
- 插件源码和发布 ZIP 各 84 个文本目标通过严格 UTF-8 无 BOM 检查；
- 发布 ZIP 共 86 个文件，不包含 Python 缓存；
- `game-production-pipeline-v0.4.0-alpha.2.zip` SHA-256：`19ffff455a5a54802fb63e16a20528dee5fb330c27cba202c952c90d8b0bd0e1`；
- 现有游戏项目没有被迁移、改写 managed block 或修改 plugin lock。

详细命令见 `v0.4.0-alpha.2-test-guide.md`。

## 当前限制

- 迁移只支持 `v0.3.0-alpha.1` 的三个已知已发行 framework digest；
- 迁移器是多文件备份与补偿式回退，不是数据库事务；进程被强制终止时应根据备份清单检查并显式回退；
- 默认备份位于项目的 `.cache`，适合迁移回退，不替代项目 Git、磁盘快照或异地备份；
- 项目简报仍由文件契约、Skill 和校验器协作，没有 MCP 或 Hook 阻止所有手工绕过；
- 只有 Godot 适配层，Unity 和其他引擎尚未验证；
- Windows PowerShell 5.1 的默认读取编码没有改变，仍需显式 `-Encoding UTF8`。

## 安装验证

本 Alpha 版本建议先安装到隔离环境。从已配置的个人 Marketplace 安装，并新建 Codex 任务加载新版本：

```powershell
codex plugin add game-production-pipeline@personal
codex plugin list
```

预期 `game-production-pipeline@personal` 显示为 `installed, enabled`。不要在尚未审阅迁移计划时直接对现有项目运行 `--apply`。
