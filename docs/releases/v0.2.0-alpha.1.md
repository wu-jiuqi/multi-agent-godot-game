# v0.2.0-alpha.1 — 可审计组织与多 Agent 可视化

## 版本定位

这是 `muti-agent` 通用游戏制作多 Agent 框架的第二个 Alpha 预发布版本。

本版本把“项目需要哪些 Agent、它们如何组成部门、哪些变化等待人工批准、哪些实例正在运行”从自然语言约定升级为可校验、可重放、可视化的 Organization Registry。它适合进入真实项目试运行，但尚未经过完整生产闭环，不是稳定版本。

## 相比 v0.1.0-alpha.1 的新增内容

- Department、Agent Preset、Position、Agent Instance 和 Temporary Grant 的可执行 Snapshot 契约；
- 每项目单一全局 revision、不可变类型化 Event、并发水位和 SHA-256 摘要链；
- Organization Change Set、人工审批绑定、批准与应用分离、stale 基线检查；
- 避免治理事件令 Change Set 自我失效的 `decision_basis_digest`；
- 只允许确定性保留令牌的批准后物化规则，防止批准内容被任意补写；
- 正式编制、运行实例和待审批变化三类确定性 Mermaid/SVG 视图；
- 项目级完整组织图与按 Department scope 生成的部门编制图；
- 有限 Temporary Grant：额度内临时实例无需逐个事前审批，但必须创建即登记、可见、可审计；
- Organization Snapshot、Change Set、Event History、层级/汇报环、Preset、授权、临时额度和摘要一致性校验；
- 通用核心与 Agent Preset、Skill、Workflow、Provider、Adapter、项目覆盖层之间的可插拔边界。

## 人工审批规则

- 所有长期 Department、Position、正式 Preset 绑定、权限上限和独立验收关系变化都需要人类批准；
- 人类批准的是结构化 Change Set 摘要和决策基线，不是 Mermaid/SVG；
- `approved_pending_apply` 不是已生效，只有后续类型化 apply Event 能原子修改正式组织；
- 正式编制、治理绑定、临时授权、ID 占用或 tombstone 改变后，旧 Change Set 必须标记 `stale` 并重新确认；
- 已批准 Temporary Grant 范围内的临时实例允许自主创建，但每个实例都必须先登记并进入运行视图。

## 验证结果

- 39 项自动测试全部通过；
- Organization 四份模板与完整 Alpha 示例校验通过；
- Event History 能够完整重建示例 Snapshot，篡改摘要会被拒绝；
- 部门层级环、Position 汇报环、无效经理、Preset 越权和临时额度漂移会被拒绝；
- 治理队列水位变化不会令 Change Set 自我失效，正式编制变化会正确触发 `stale`；
- Mermaid/SVG 输出确定、携带水位和摘要，并能区分正式、临时、待审批与拟新增节点；
- v0.1 的 Pipeline Contract、Loop Registry 和回放闸门测试保持通过。

验证命令：

```powershell
python -m unittest discover -s game/tests -p 'test_*.py' -v
python game/scripts/validate_pipeline_contract.py game/contracts/examples/vertical-slice-greybox.yaml
python game/scripts/validate_organization_registry.py --templates --snapshot game/contracts/examples/organization-alpha-snapshot.yaml --change-set game/contracts/examples/organization-alpha-change-set.yaml
python game/scripts/render_organization.py --snapshot game/contracts/examples/organization-alpha-snapshot.yaml --change-set game/contracts/examples/organization-alpha-change-set.yaml --view change --scope dept:sample-game:design --format mermaid
```

## 当前限制

- Organization Registry 仍是文件契约、校验器和参考重放器，尚无数据库或并发事务适配器；
- 尚未提供交互式组织图编辑器；当前 Mermaid/SVG 是只读投影，修改必须回到 Change Set；
- The Nameless Vessel 前向样本尚未跑通从项目画像、项目专属编制到 `GATE-2` 灰盒的完整闭环；
- `game/skills/` 尚未沉淀经过两个真实样本验证的稳定通用 Skill；
- 当前只有 Godot 适配层，尚未验证 Unity 或其他引擎；
- 临时授权的时间比较、成本计量与持久化锁需要由具体运行适配器实现。

## 下一阶段

1. 在 The Nameless Vessel 建立真实 Organization Snapshot，并由项目编制设计 Agent 生成首个待审批 Change Set 与组织图；
2. 对首个批准 Change Set 执行完整的决定、应用、事件重放和失败回退；
3. 运行项目定义、内容设计、Godot 灰盒、独立 QA 和人工 `GATE-2`；
4. 根据真实并发与恢复需求选择 Organization/Loop Registry 持久化适配器；
5. 复盘两个样本的重复方法，决定首批稳定 Skill。
