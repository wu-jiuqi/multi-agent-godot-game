# v0.4.0-alpha.4 — 专业资产 Contract 全流程闭环

`v0.4.0-alpha.4` 把专业资产公共底座从独立 P0 Contract 接入项目 Bootstrap、P6 生产 Loop、A0–A3 Asset Gate、Loop Registry、Godot 交接和项目总校验，统一管理资产需求、可编辑 Source、Runtime、权利链、版本、导入配方、目标平台性能证据与原因码返修。

## 核心变更

- 新增 `specialist-asset-production` Loop Contract：`ready / active / review / completed` 分别绑定 A0 / A0 / A2 / A3；
- Asset Contract 改为分阶段校验：A0 不再错误要求尚未生产的 Source、Runtime 和性能数据；
- A0–A3 统一要求需求评审、生产者自检、意图、技术、QA、权利六类可追溯记录；
- 新增只读 Gate Evaluator，明确输出 `pass / revise / blocked / awaiting_human`，自动检查不代替人工决定；
- Loop Registry 只保存稳定资产 ID、revision、`repo://` URI、文件 SHA-256、Contract subject digest 和 Gate 证据，不复制资产正文；
- 项目总校验自动发现 Asset Contract 和专业资产 Loop；引用丢失、摘要漂移、Gate 缺失或用普通 Loop 冒充专业资产 Loop 时 fail closed；
- Bootstrap 建立资产 Contract、预算、证据、权利、受保护路径快照以及 Loop Contract/Registry 控制面；
- Godot 适配只接收已冻结资产引用与导入证据，不把引擎缓存当权威 Runtime；
- 增加从 `v0.3.0-alpha.1`、`v0.4.0-alpha.2`、`v0.4.0-alpha.3` 到本版本的显式迁移路径。

## UI 边界

本次接入不修改 UI Screen/Flow、布局、交互协议或现有 UI 实现。专业资产层只读消费经批准的 UI 等领域事实源；`generated_outputs` 与 `protected_paths` 重叠时阻断。迁移与验证测试会对既有 UI 文件做逐字节摘要比对，任何变更必须另开上游 UI 工作流。

## 验收结果

- 全量自动化测试：107 项通过；
- 文本编码、静态 Contract、A3 Gate、Loop Registry、项目实例与迁移回归均纳入发布门禁；
- `compileall`、`git diff --check` 与两次确定性 ZIP 构建纳入发布检查；
- 当前结论：公共框架已形成机器可验证闭环，仍需在首个真实项目回放目标平台预算、真实 DCC/导入链和发布资产证据，因此保持 alpha、不是 Production Ready。

## 兼容与迁移

迁移先 dry-run，再由项目所有者批准精确 `plan_digest`。它只补充缺失的资产/Loop 控制面 README、更新 `AGENTS.md` managed block、写审批记录并最后更新 `plugin-lock.yaml`；已有 README 逐字节保留，不修改 Asset Contract、Snapshot、Event History、游戏内容或 UI 事实源。未知旧版框架摘要、计划后文件漂移或损坏的 managed block 都会阻断并自动回退。
