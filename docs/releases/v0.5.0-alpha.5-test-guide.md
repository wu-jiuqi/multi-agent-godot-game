# v0.5.0-alpha.5 测试手册

## 回归命令

从仓库根目录运行：

~~~powershell
python -m unittest discover -s game/game-production-pipeline/tests
python game/game-production-pipeline/scripts/validate_execution_plan.py game/game-production-pipeline/contracts/examples/sample-execution-plan.yaml
python game/game-production-pipeline/scripts/validate_production_charter.py game/game-production-pipeline/contracts/examples/sample-production-charter.yaml
python game/game-production-pipeline/scripts/build_release.py
~~~

结构示例为合成数据、draft 状态；没有实际审批，不可启动生产。带 --project-root 的测试使用临时目录中真实文件及明确标注的合成审批，验证文件内容和故障路径，不声称真实人类已经批准游戏。

## 必须覆盖的行为

- 初始 GATE-0/GATE-1/D2 和 Charter 需精确人类来源、时间和摘要；缺失、漂移、非人类决定拒绝启动。
- 简报变化、工具源变化、未知权限、越界路径、成本和重试超限阻断。
- 只有实际产出、自检和独立审核完成后才能记录完成。
- 真实修改产物后可从失败恢复，旧快照仍可验证；不能复用旧自检替代新尝试。
- DAG 环、无序重叠写、容量超限、未完成汇聚依赖阻断；并行不同文件可以推进。
- 同事件重复追加幂等，变体、损坏链、竞争写锁及替换账本拒绝。
- 委派 Gate 需匹配标准和当前证据；自审、缺失标准、陈旧证据不得通过。
- D4 receipt 不替代既有物理资产和引擎基准检查；初始画风不能由 Agent 签署。
- alpha.4 白名单迁移、适配器与绑定事务及回滚保留旧数据。
- Bootstrap 创建预算为零的草案；现有无 Charter 项目仍可按旧模式校验。

## 真实项目试运行

选择一个范围小且可观察的游戏原型。在共同立项中固定范围、体验、风格、模型/工具、预算、验收和通知偏好，再授权实际执行。记录有效完成、首次通过、修复、接管和实际用量；遇到边界事件集中决策。结束后检查可运行构建及真实体验。此项尚待实施，不能用单元测试替代。

## 编码与安装检查

插件安装来源需要先指向本版；源码更新不会自动替换 Codex 当前加载的缓存：

~~~powershell
codex plugin add game-production-pipeline@personal
codex plugin list
~~~

确认实际版本与 installed, enabled 状态。已有项目先迁移 dry-run；审批只针对审阅过的摘要。不要直接改 managed block 或 plugin-lock.yaml 来绕过迁移。

Windows PowerShell 5.1 读取中文 UTF-8 无 BOM 文件：

~~~powershell
Get-Content -LiteralPath "文件路径" -Encoding UTF8
~~~

chcp 65001 不改变旧 PowerShell 的默认文件编码；可用 PowerShell 7 复核。源码和 ZIP 文本统一 UTF-8 无 BOM、LF。
