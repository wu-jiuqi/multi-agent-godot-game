# 人工审批闸门

人工闸门负责项目所有者保留的方向与体验判断。自动检查通过不等于人工闸门通过，人工喜欢某个方案也不能替代技术检查。

## 立项授权与后续专业验收

新项目优先在立项阶段共同确认 GATE-0/GATE-1 与适用的 D2 初始视觉方向，并把职责、预算、验收条件和授权写入 `production-charter.yaml`。可以在同一立项包中批准这些具体对象，不能预签未知结果。

启动授权书可将 GATE-2/GATE-3/D4 的规格符合性验收交给指定的独立 Agent。该 Agent 必须检查当前产物、未过期证据和固定标准，记录真实身份与授权书摘要；不伪造 human 审批，不省略测试，也不将判断升级为玩家体验已获人类认可。改变初始体验或画风仍返回人类。

GATE-4 的制作完成与对外发布分别处理。未授权外部发布时先自主完成测试、构建和发布包；只有明确覆盖发布目标、范围与条件的授权才能执行外部动作。没有有效授权书的旧项目继续使用下述人工流程。

## `GATE-0` 范围批准

发生在 P0 结束后。

人类确认：

- 核心玩家幻想和设计支柱值得继续；
- 目标平台、受众、时长和内容量可接受；
- `MUST / SHOULD / WON'T` 已经明确；
- 当前范围与时间、预算和团队能力匹配。

未通过则返回 `AGT-GD` 修订 P0，不得进入完整系统和内容设计。

## `GATE-1` 核心体验假设批准

发生在 P1 以及垂直切片简报完成后。

人类确认：

- 核心循环和 Player Verbs 能表达目标体验；
- 胜利、失败、恢复与反馈形成可测试闭环；
- 垂直切片足以验证最大风险，而不是只展示最容易实现的内容；
- Godot 技术可行性证据没有暴露不可接受的成本。

未通过优先返回 P1；若问题来自范围，则返回 P0。

## `GATE-2` 灰盒冻结

发生在关卡灰盒可完整游玩后，是进入高成本资产生产的前置。

人类确认：

- 玩家能理解目标、路线和关键反馈；
- 关卡节奏、空间可读性与失败恢复符合预期；
- 玩法、剧情节点和交互对象在同一体验中成立；
- 已知问题不要求大规模推翻空间结构。

未通过按问题类型返回 P1、P2、P4 或 P5。未经批准不得批量制作最终环境资产。

## `GATE-3` 内容与集成冻结

发生在正式资产、UI、音频和功能集成后。

人类确认：

- 表达与目标风格、情绪和角色意图一致；
- 本次范围内每项专业资产都存在通过 A3 的冻结 Contract、授权、导入、性能与返修证据；
- 关键内容不再进行结构性增加；
- 剩余问题可通过修复和调优解决；
- 变更范围已经收敛，可以进入发布候选测试。

未通过返回相应资产专业能力、P5 或 P7；影响核心体验时必须继续回退到上游。单项资产 A3 只证明该 revision 可集成，不能替代项目级 `GATE-3` 的整体体验判断。

## `GATE-4` 发布批准

发生在 P9 发布候选验证完成后。

人类确认：

- 阻断性问题已清零，已知风险可接受；
- 目标平台构建、存档兼容和关键路径证据完整；
- 版本说明、分发设置和回滚方案有效；
- 当前构建可以成为对外版本。

`AGT-QA` 不能自行产生外部发布授权。启动时已有精确发布授权的，由指定审核者核验当前候选、目的地、额度和条件；没有授权则交付发布包并等待所有者决定。
