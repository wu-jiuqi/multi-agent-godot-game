# v0.3.0-alpha.1 — Codex 插件化与项目实例化

## 版本定位

这是 `muti-agent` 游戏制作多 Agent 框架的第一个可安装 Codex 插件版本。它把通用框架与具体游戏内容分离：插件提供组织、授权、审批、生产循环和引擎适配方法，目标游戏项目保存自己的事实、设计决策、Agent Presets、Skills、运行状态与证据。

该版本适合在隔离项目中安装和验证，仍是 Alpha 预发布版本；The Nameless Vessel 的真实前向生产闭环尚未执行，因此不应标记为稳定或 Production Ready。

## 新增内容

- 标准 `.codex-plugin/plugin.json` 插件清单与个人 Marketplace 安装结构；
- 五个可被 Codex 发现的核心 Skills：项目初始化、组织设计、生产循环、门禁审查和 Godot 适配；
- `game-pipeline/` 项目控制面，以及 `.agents/skills/` 项目 Skill 与 `.codex/agents/` 生成适配层；
- proposal-first 初始化：dry-run 展示完整文件影响和 SHA-256 审批摘要，精确确认后才写入；
- 空 Organization Registry Genesis、可重放 Event History、初始编制草案与托管 `AGENTS.md`/`.gitignore` 区块；
- 严格 `plugin-lock.yaml`：版本不一致进入只读，相同版本但框架摘要漂移直接阻断；
- 只读迁移预检：没有显式 migrator、dry-run、人工批准和回退要求时拒绝迁移；
- 项目 Agent Preset、人工审批记录和 Skill Binding 模板；
- 只从已批准且摘要匹配的 Preset 生成 `.codex/agents/*.toml`，拒绝覆盖用户维护的 Agent；
- 项目实例总校验器，把插件锁、Registry 重放、Change Set、审批、Skill 绑定和 Agent 适配器新鲜度合并为一个结果；
- 旧有 Pipeline、Loop、Organization、渲染与回放能力全部迁入可移植插件根目录。

## 审批与运行边界

- 所有长期 Department、Position、Agent Preset、Skill Binding、授权上限和独立验收关系变化必须由人类批准；
- 批准的是结构化对象和不可变摘要，不是图像、自然语言概述或自动测试结果；
- 已批准 Temporary Grant 范围内的临时 Agent Instance 可以免逐实例事前审批，但仍必须先登记、受额度约束并保持可见；
- 插件治理授权、Codex 沙箱权限和技术验收相互独立；
- 插件初始化不会自动创建项目经理、部门或功能 Agent，只会建立空基线和待补全草案。

## 验证结果

- 插件清单通过 Codex `validate_plugin.py`；
- 五个 Skill 全部通过 `quick_validate.py`；
- 51 项自动测试全部通过，其中包含原有 39 项契约测试和 12 项插件包/运行时测试；
- 隔离临时项目完成 dry-run、错误摘要拒绝、正确摘要应用、幂等重跑、Registry 重放和项目总校验；
- 冲突文件、损坏托管区块、非托管 Codex Agent、缺失审批、过期 Preset 摘要和 Skill 漂移均会 fail closed；
- 已批准 Preset 能生成可被 Python `tomllib` 解析的 Codex Agent TOML；
- 版本不一致进入 `read_only`，缺少显式 migrator 的迁移保持阻断；
- 安装目录中的插件包通过插件校验；
- 发布后使用 `codex plugin add game-production-pipeline@personal` 完成首次安装，`codex plugin list` 显示 `installed, enabled`；

## 首次安装

把插件放到 `~/plugins/game-production-pipeline/` 并创建默认个人 Marketplace 条目后，先确认 Codex 已发现插件源：

```powershell
codex plugin marketplace list
codex plugin list
```

然后通过 CLI 完成首次安装：

```powershell
codex plugin add game-production-pipeline@personal
codex plugin list
```

预期状态为 `installed, enabled`。首次安装前，设置页的插件搜索可能不会显示尚未安装的个人插件；这不代表 Marketplace 或插件源无效。安装后必须新建 Codex 任务，当前任务不会热刷新 Skills。

## 当前限制

- 治理约束目前由 Skill、文件契约和确定性脚本执行，没有 MCP 或 Hook 强制拦截所有绕过行为；
- Registry 尚无数据库或跨文件事务适配器；
- 当前没有真实版本迁移器，只有 fail-closed 迁移预检；
- Personal Marketplace 的首次安装需要执行 `codex plugin add game-production-pipeline@personal`；设置页搜索不能替代安装状态检查，当前任务也不能热刷新 Skill 列表；
- 只有 Godot 适配层，尚未验证 Unity 或其他引擎；
- The Nameless Vessel 前向样本尚未执行，真实编制、循环恢复、人机门禁和 `GATE-2` 仍待验证。

## 下一阶段

1. 对 The Nameless Vessel 使用 `$bootstrap-game-pipeline` 先生成只读初始化计划；
2. 人工确认初始化摘要后，建立空项目 Registry；
3. 使用 `$design-game-organization` 共同确定首个项目编制 Change Set 和组织图；
4. 逐项批准后生成项目 Codex Agents，再运行最小垂直切片到 `GATE-2`；
5. 根据真实绕过、并发和恢复问题决定是否在后续版本增加 MCP、Hook 或持久化事务适配器。
