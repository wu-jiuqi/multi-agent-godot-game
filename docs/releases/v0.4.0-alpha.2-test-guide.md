# v0.4.0-alpha.2 测试与发布验收手册

## 目标

验证 v0.3→v0.4 迁移器只在明确版本与框架摘要上工作，dry-run 不写文件，apply 必须绑定人工批准的精确摘要，写入失败能自动回退，成功迁移可以显式回退，且项目简报、managed block、plugin lock、中文编码和发布包语义保持一致。

所有迁移测试必须使用临时项目或现有项目的隔离副本。不得直接在 `D:\A Cat in Fleeting Light`、`D:\The Nameless Vessel` 或其他生产项目上执行 `--apply`。

## 环境

- Windows PowerShell 5.1 或 PowerShell 7；
- Python 3.11+；
- PyYAML；
- 仓库根目录：`D:\Agent\muti-agent`；
- 插件根目录：`D:\Agent\muti-agent\game\game-production-pipeline`。

Windows PowerShell 5.1 读取中文文件时使用：

```powershell
Get-Content -LiteralPath "文件路径" -Encoding UTF8
```

`chcp 65001` 只调整控制台代码页，不保证 `Get-Content` 使用 UTF-8。PowerShell 7 或明确配置为 UTF-8 的编辑器一般可以直接读取。乱码出现时不得覆盖 managed block、`plugin-lock.yaml` 或批量转码项目文件。

## 一、静态与单元测试

```powershell
Set-Location D:\Agent\muti-agent

python -m compileall -q `
  game\game-production-pipeline\scripts `
  game\game-production-pipeline\migrations `
  game\game-production-pipeline\tests

python -m unittest discover `
  -s game\game-production-pipeline\tests `
  -p 'test_*.py' `
  -v
```

专项测试至少覆盖：

- dry-run 前后文件集合和字节完全相同；
- 计划列出项目简报、说明、Fact Sources、`AGENTS.md` 和 plugin lock 的前后摘要；
- 错误 `approval_digest` 在创建备份和项目写入前停止；
- 未知 v0.3 framework digest fail closed；
- 已有用户项目简报不被覆盖；
- apply 后 plugin lock 与项目实例均为 `normal`；
- 再次规划返回 `no_change`；
- 后置验证失败会自动按字节回退；
- 显式回退恢复旧文件并删除迁移创建文件；
- 迁移后目标文件漂移时回退拒绝覆盖。

## 三、bootstrap 回归

在全新临时目录执行 bootstrap dry-run、apply 和第二次 apply，确认：

- dry-run 不创建 `game-pipeline/`；
- 首次 apply 创建项目简报；

- `validate_plugin_lock.py` 和 `validate_project_instance.py` 均为 `normal`。

## 四、迁移 CLI 验收

准备一个由测试夹具生成的 v0.3 隔离实例，然后执行：

```powershell
$plan = python game\game-production-pipeline\scripts\migrate_plugin.py `
  --project-root D:\Temp\gpp-v03-fixture | ConvertFrom-Json

if ($plan.outcome -ne 'migration_ready') { throw '迁移预检未就绪' }

python game\game-production-pipeline\scripts\migrate_plugin.py `
  --project-root D:\Temp\gpp-v03-fixture `
  --migration-at $plan.migration_at `
  --apply `
  --approval-digest $plan.plan_digest `
  --approved-by human:owner
```

迁移后执行：

```powershell
python game\game-production-pipeline\scripts\validate_plugin_lock.py `
  --project-root D:\Temp\gpp-v03-fixture

python game\game-production-pipeline\scripts\validate_project_instance.py `
  --project-root D:\Temp\gpp-v03-fixture

python game\game-production-pipeline\scripts\migrate_plugin.py `
  --project-root D:\Temp\gpp-v03-fixture `
  --migration-at $plan.migration_at
```

预期依次为 `normal`、`normal` 和 `no_change`。

回退测试：

```powershell
python game\game-production-pipeline\scripts\migrate_plugin.py `
  --project-root D:\Temp\gpp-v03-fixture `
  --rollback `
  --plan-digest $plan.plan_digest `
  --confirm-rollback $plan.plan_digest
```

回退后旧 plugin lock 恢复，当前插件校验应回到 `read_only`；不得只回写版本号。

## 五、中文编码专项检查

```powershell
python game\game-production-pipeline\scripts\validate_text_encoding.py `
  --plugin-root game\game-production-pipeline
```

严格要求：

- Markdown、YAML、JSON、TOML、Python、迁移器和文本模板均能严格 UTF-8 解码；
- 不含 BOM 或 `U+FFFD`；
- `项目 Agent Presets`、`人工审批记录`、`建立项目初始多 Agent 编制`、`项目管线状态位于` 等原文存在；
- 迁移后的项目简报、审批记录、managed block 与 Fact Sources 中文可回读；
- 校验脚本不修改被检查文件。

## 六、发布包与 SHA-256

```powershell
python game\game-production-pipeline\scripts\build_release.py `
  --plugin-root game\game-production-pipeline `
  --output-dir dist

python game\game-production-pipeline\scripts\validate_text_encoding.py `
  --plugin-root game\game-production-pipeline `
  --zip dist\game-production-pipeline-v0.4.0-alpha.2.zip

Get-FileHash `
  -LiteralPath dist\game-production-pipeline-v0.4.0-alpha.2.zip `
  -Algorithm SHA256

Get-Content `
  -LiteralPath dist\game-production-pipeline-v0.4.0-alpha.2.zip.sha256 `
  -Encoding UTF8
```

实际摘要必须与 sidecar 完全一致；ZIP 必须包含迁移模块、迁移执行器、全部 Skills、测试和 UTF-8 校验器，不得包含 `__pycache__`、`.pyc` 或 `.pyo`。

```powershell

```

两者输出必须保持不变。不得修改其 managed block、`game-pipeline/plugin-lock.yaml` 或项目内容。

- bootstrap 与迁移的 dry-run、apply、幂等和回退验证通过；

- ZIP 摘要与 sidecar 一致；
- 现有游戏项目没有变化；
