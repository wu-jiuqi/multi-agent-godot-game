## 换行与跨环境复现

```powershell
git check-attr text eol -- game/game-production-pipeline/agents/art-director.md
git check-attr text eol -- game/game-production-pipeline/.gitattributes
python -m unittest game/game-production-pipeline/tests/test_text_encoding.py -v
```

文本文件必须显示 `text: auto` 和 `eol: lf`。自动化测试会把完整插件复制到临时 Git 仓库，分别使用 `core.autocrlf=true` 和 `false` 导出；两次构建的 framework digest 和 ZIP SHA-256 必须相同。

将任一发布源 Markdown/YAML/Python 文件改为 CRLF 后，编码校验和发布构建都必须以 `non-lf-line-ending` 阻断，不允许在构建阶段静默转码。常见图片、字体、DCC 文件和 ZIP 必须保持 binary。

## ZIP 字节契约

- 所有成员使用 `ZIP_STORED`，不依赖当前 Python 链接的 zlib 版本。
- 路径按字典序，时间戳固定为 `1980-01-01 00:00:00`，Unix 文件模式固定为 `100644`。
- ZIP 内不得包含 `.git`、`__pycache__`、`.pyc`、`.pyo`、临时文件或工作区密钥。
- `.sha256` sidecar 必须回读为 `<digest>  <filename>`。

## v0.5.0-alpha.1 迁移

```powershell
$plan = python game/game-production-pipeline/scripts/migrate_plugin.py `
  --project-root <project> | ConvertFrom-Json

$plan.outcome
$plan.actions
$plan.plan_digest
```

LF 发布摘要 `1a06826e…` 和已知 CRLF 物化摘要 `56a98f18…` 都应返回 `migration_ready`；未知摘要必须返回 `migration_blocked`。`actions` 只允许包含 `AGENTS.md` 和 `game-pipeline/plugin-lock.yaml`。

只有项目所有者审阅完整计划并批准精确 `plan_digest` 后才能执行 `--apply --approval-digest <digest>`。应用后项目总校验必须为 `normal`，重复规划返回 `no_change`；不得修改现有美术、资产、DCC、场景、UI、组织、Snapshot 或 Event History。

## 旧版本直迁

`v0.3.0-alpha.1`、`v0.4.0-alpha.2`、`v0.4.0-alpha.3` 和 `v0.4.0-alpha.4` 的白名单回归应继续生成主美控制面 README、`AGENTS.md` 与 lock 动作。已有 README 必须逐字节保留，未知摘要、损坏 managed block 和计划后漂移仍 fail closed。禁止只把 `plugin-lock.yaml` 改回旧版本。
