# v0.4.0-alpha.1 测试手册

本手册验证项目经理启动模式、项目简报审批边界、中文 UTF-8 编码、发布包和旧项目隔离。所有写入测试必须使用临时项目；不得修改任何现有游戏项目。

## A. 仓库、插件与编码规范

在仓库根目录执行：

```powershell
python -m unittest discover -s game/game-production-pipeline/tests -p "test_*.py" -v
python -m compileall -q game/game-production-pipeline/scripts game/game-production-pipeline/tests
python C:\Users\<user>\.codex\skills\.system\plugin-creator\scripts\validate_plugin.py game\game-production-pipeline
python game\game-production-pipeline\scripts\validate_text_encoding.py `
  --plugin-root game\game-production-pipeline
```

再对六个 `game/game-production-pipeline/skills/*` 目录分别执行 `quick_validate.py`。预期：全部单元测试、插件清单、六个 Skill 和编码检查通过。编码结果必须为结构化 JSON，`state` 为 `valid`，`errors` 为空，且校验过程中没有文件变化。

新校验器与构建器使用 ASCII-safe JSON 输出。PowerShell 5.1 代码页 936 下可能看到 `\u9879\u76ee` 形式的 JSON 转义；这是合法 JSON，解析后恢复为中文，不代表源文件乱码。

编码规范：插件源码、模板、生成文件和发布 ZIP 内文本统一为 UTF-8 无 BOM。不得用隐藏的自动转码修复失败。

## B. Windows PowerShell 5.1 中文读取

Windows PowerShell 5.1 的默认文件读取编码可能使用本地 ANSI 代码页。读取中文文件时显式指定 UTF-8：

```powershell
Get-Content -LiteralPath "文件路径" -Encoding UTF8
```

`chcp 65001` 只调整控制台代码页，不保证 `Get-Content` 使用 UTF-8。PowerShell 7 或明确配置为 UTF-8 的编辑器一般可以直接读取。

看到乱码时先运行上面的命令重新读取，再执行 `validate_text_encoding.py`。不要直接覆盖 `AGENTS.md` managed block，不要手工修改 `game-pipeline/plugin-lock.yaml`，也不要批量转码项目文件。

## C. 隔离项目 bootstrap、回读与幂等

以下示例只创建系统临时目录：

```powershell
$pluginRoot = (Resolve-Path "game\game-production-pipeline").Path
$tempProject = Join-Path ([IO.Path]::GetTempPath()) ("gpp-v040-" + [guid]::NewGuid().ToString("N"))
New-Item -ItemType Directory -Path $tempProject | Out-Null
$createdAt = "2026-08-15T10:00:00Z"

$planJson = python "$pluginRoot\scripts\bootstrap_game_pipeline.py" `
  --plugin-root $pluginRoot `
  --project-root $tempProject `
  --project-id encoding-game `
  --project-name "流光里的猫" `
  --engine Godot `
  --created-at $createdAt
$plan = $planJson | ConvertFrom-Json
if (Test-Path (Join-Path $tempProject "game-pipeline")) { throw "dry-run 写入了项目" }

python "$pluginRoot\scripts\bootstrap_game_pipeline.py" `
  --plugin-root $pluginRoot `
  --project-root $tempProject `
  --project-id encoding-game `
  --project-name "流光里的猫" `
  --engine Godot `
  --created-at $createdAt `
  --apply `
  --approval-digest $plan.approval_digest
if ($LASTEXITCODE -ne 0) { throw "bootstrap apply 失败" }

python "$pluginRoot\scripts\bootstrap_game_pipeline.py" `
  --plugin-root $pluginRoot `
  --project-root $tempProject `
  --project-id encoding-game `
  --project-name "流光里的猫" `
  --engine Godot `
  --created-at $createdAt `
  --apply `
  --approval-digest $plan.approval_digest
if ($LASTEXITCODE -ne 0) { throw "bootstrap 幂等重跑失败" }
```

检查输出：第一次 apply 创建文件，第二次 apply 的 `applied` 为空且目标均为 `unchanged`。以下文件必须按 UTF-8 回读并包含原文：

```powershell
Get-Content -LiteralPath "$tempProject\game-pipeline\agents\README.md" -Encoding UTF8
Get-Content -LiteralPath "$tempProject\game-pipeline\approvals\README.md" -Encoding UTF8
Get-Content -LiteralPath "$tempProject\game-pipeline\organization\change-sets\initial-organization.draft.yaml" -Encoding UTF8
Get-Content -LiteralPath "$tempProject\AGENTS.md" -Encoding UTF8
```

代表性原文分别为：

- `项目 Agent Presets`
- `人工审批记录`
- `建立项目初始多 Agent 编制`
- `项目管线状态位于`

## E. 项目简报与组织设计准入

1. 把项目所有者提供的玩法、美术方向、实现概要和约束登记为来源与 statements；
2. 明确区分 `confirmed / preference / hypothesis / unknown`；
3. 保留至少一个 `blocks_staffing=true` 问题，确认校验器拒绝 `staffing_input.readiness=ready`；
4. 补齐阻断项和责任需求，运行 `validate_project_brief.py`；
5. 审阅完整简报和 `subject_digest`；未获得人工确认前不得写入 `confirmed`；
6. 创建摘要匹配的 `project-brief` 审批记录并重检；
7. 修改任一已批准 statement，确认旧摘要和审批失效。

draft、blocked、缺审批或摘要过期的简报必须返回 `$prepare-game-project-brief`；只有 confirmed 且 staffing-ready 的简报才能进入 `$design-game-organization`。

## F. 构建 ZIP 与 SHA-256

从仓库根目录执行：

```powershell
python game\game-production-pipeline\scripts\build_release.py `
  --plugin-root game\game-production-pipeline `
  --output-dir dist
if ($LASTEXITCODE -ne 0) { throw "发布包构建失败" }

$zipPath = (Resolve-Path "dist\game-production-pipeline-v0.4.0-alpha.1.zip").Path
$shaPath = (Resolve-Path "dist\game-production-pipeline-v0.4.0-alpha.1.zip.sha256").Path
python game\game-production-pipeline\scripts\validate_text_encoding.py `
  --plugin-root game\game-production-pipeline `
  --zip $zipPath
if ($LASTEXITCODE -ne 0) { throw "发布 ZIP 编码校验失败" }

$actual = (Get-FileHash -LiteralPath $zipPath -Algorithm SHA256).Hash.ToLowerInvariant()
$expected = ((Get-Content -LiteralPath $shaPath -Encoding UTF8).Split()[0]).ToLowerInvariant()
if ($actual -ne $expected) { throw "SHA-256 不匹配" }
```

预期 ZIP 只包含 `game-production-pipeline/` 根下文件，不包含 `__pycache__`、`.pyc` 或临时文件；所有目标文本严格按 UTF-8 解码、无 BOM、无 `U+FFFD`，代表性中文存在。

## G. 现有项目隔离

测试前后分别记录现有游戏项目的 `git status --short`。本次发布不得：

- 修改任何项目的 managed block；
- 手工修改任何项目的 `game-pipeline/plugin-lock.yaml`；
- 批量转码任何现有项目文件；
- 为消除显示乱码重新初始化项目；
- 把 v0.4 文件复制进锁定 v0.3 的项目伪装迁移。

## H. 发布验收

只有 A～G 全部通过后才允许：

1. 按功能拆分并检查 Git diff；
2. 推送当前分支；
3. 创建并推送 `v0.4.0-alpha.1` 标签；
4. 创建 GitHub Release；
5. 上传 `game-production-pipeline-v0.4.0-alpha.1.zip`、`.sha256` 和本发布说明，并将 GitHub Release 标记为 Pre-release、关闭 Set as latest。

若远端权限或发布工具不可用，停止 Release 创建并明确报告阻塞，不得伪造成功。

发布完成且当前环境允许切换插件后，执行：

```powershell
codex plugin add game-production-pipeline@personal
codex plugin list
```

预期 `game-production-pipeline@personal` 显示为 `installed, enabled`。重新安装后必须新建 Codex 任务；当前任务不会热刷新 Skills。
