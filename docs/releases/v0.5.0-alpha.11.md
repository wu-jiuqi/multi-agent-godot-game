# v0.5.0-alpha.11

## 主题

把 Codex Figma UI 四步生产流程纳入发布版：先理解产品资料，再确定产品身份和视觉方向，复用或补齐 UX 流程，最后通过 Figma 插件制作可交接的视觉系统和页面原型。

## 本版变更

- `ui-production` 默认采用 Figma-first 顺序：输入资料提取、产品身份与 slogan、UX 流程、Figma 视觉系统原型。
- `ui-production` Agent 默认负责 Figma 设计交付；Godot 场景实现保留为后续可选阶段。
- UI 交接契约增加工作流阶段、来源文档、产品身份、视觉方向、UX 来源和 Figma prototype 绑定信息。
- 增加 `validate_art_direction_contract.py --ui-figma-only`，可在没有 Godot Theme 或场景时验证 Figma-only 交付。
- Figma 文件和节点必须绑定到 `file_key`；本地 brief/PRD/GDD 与 snapshot 使用 SHA-256，远程来源只记录 provenance，不把下载内容伪装成本地证据。
- 增加可选 Figma 工具注册表条目模板；默认工具注册表仍保持 fixture-only，避免把本地模拟工具误认为真实插件。
- 新增从 alpha.10 到 alpha.11 的受摘要保护迁移，并保留历史已发布版本到 alpha.11 的直接迁移入口。迁移只更新托管元数据、绑定、Adapter 和 plugin lock，不改写项目已有场景、资源、UI、Event History 或业务事实。

## 验收边界

Figma-only 交付必须明确四个阶段的状态、输入来源和证据；如果 PRD 已经提供 UX 流程，契约应记录 `inherited_from_prd` 或 `authoring_skipped`，不能重复编造一套流程。Figma 文件、页面或节点 URL 只能指向对应 `file_key`，本地快照必须能在仓库中复核。Godot 视觉实现、输入交互和目标构建仍属于后续任务。

## 迁移

alpha.10 项目的 framework digest `f4dbc5daac31c32760741bd887399573fa7057a918165934fb21732ff731eba2` 已加入 alpha.10→alpha.11 迁移白名单。未知摘要、缺少显式迁移器、非托管 Adapter、损坏 managed block 或计划后文件漂移都会 fail closed。迁移必须保留 managed block 和 `plugin-lock.yaml`，不能手工改锁文件绕过审批。

## 安装

插件与独立 UI Skill 分开安装；插件 ZIP 不会自动安装独立 Skill。更新 Personal Marketplace 源后执行：

```powershell
codex plugin add game-production-pipeline@personal
codex plugin list
```

确认版本为 `0.5.0-alpha.11` 且状态为 `installed, enabled`。独立 Skill 解包到 `C:\Users\30114\.codex\skills\ui-ux-pro-max`，再回读 `SKILL.md` 与 `references/godot-production.md`。重装后需新建 Codex 会话才能加载新版 Skill。

Windows PowerShell 5.1：`Get-Content -LiteralPath "文件路径" -Encoding UTF8`；执行 `chcp 65001`，并使用 PowerShell 7 复核。迁移后仍需保留 managed block 和 `plugin-lock.yaml`。
