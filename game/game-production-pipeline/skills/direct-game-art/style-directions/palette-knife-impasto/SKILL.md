# 刮刀厚涂油画

把用户意图转为有厚颜料体积、刮刀形状和选择性画布纹理的图像，完成实际生图与交付。只在用户要求评估、提示词或演练时停留在文字阶段。本 skill 是可复用工作流，不是模型、滤镜或独立生图服务。

## 读取与适用范围

- 每次先读 [风格基线](references/style-bible.md)。它是可覆盖的默认视觉语言，不固定题材或故事。
- 多图、色卡、输入冲突或需要提示词示例时，读 [输入与提示词](references/input-and-prompt-guide.md)。
- 仅在为《心界 Mindrift》制作资源时读 [项目附加规范](references/mindrift-profile.md)。不要把项目剧情禁用项应用于其他作品。
- 如果宿主有 `imagegen` skill，按其现行工具、保存与编辑规范执行；没有该 skill 但有内置图像工具也能执行本工作流。以当前工具 schema 为准，不依赖某台电脑的路径、固定模型名称或 API 参数。
- 明确要求其他画风时以用户为准；不要自动给所有图像任务套油画风格。简单矢量/代码原生资产应交给相应工具。

## 1. 理解自由输入

三种输入均可单独使用，也可以任意组合，不要求填写表单：

| 输入 | 处理 |
| --- | --- |
| 文字 | 提取主体、用途、构图、情绪和保留/排除条件；支持中文或其他语言 |
| 色卡 | 接受 HEX、RGB、颜色名称或色卡图片；分配背景、主体、点缀、亮部与暗部角色 |
| 图片 | 判断是配色、画风、主体身份、构图参考，还是要直接修改的目标 |

只有色卡且没有主体/用途时，默认生成一张抽象厚涂色彩习作，并简短说明这一假设；不擅自补人物或故事。只有图片且没有修改指令时，默认以可见主体为题材生成油画新作，不承诺锁定原图。用户要求“只换配色”“保留房间不动”等属于编辑。

本地图片先用 `view_image` 检查；已附在会话中的图可直接观察。记录每张图的角色和必要保留项，色卡图不作为要重绘的场景。只有路径但读取失败、缺少编辑目标、或用户要求严格保留内容而目标不明时，请求缺失图片/信息，不声称已看见。

优先级：本次明确要求 > 用户为某一用途指定的参考 > 本 skill 默认值。指定色卡控制颜色，构图图控制空间关系，身份图控制角色特征；不要自动复制风格参考中的颜色或物件。明确只参考颜色时不继承原图构图。若“只用黑白”和“严格保留彩色配色”这类硬约束互斥，先问一句解决冲突；非关键缺项作合理假设后直接生图。

色号原样保留；RGB 通道含义或取值范围不清时不猜测精确转换。目测图片得到的颜色只能称为近似色，不伪称取样。未指定色卡时可用风格基线的默认配色，用户已给的颜色不可被默认酒红或奶油白覆盖。配色影响色彩关系，不代表生成图像逐像素严格匹配 HEX。

## 2. 组织生图规格

只填写和请求有关的条目，用户未要求的对象、宗教符号、故事与固定构图不要添加：

```text
Use case: stylized-concept / precise-object-edit / lighting-weather / style-transfer
Asset type: 用途与目标比例
Primary request: 用户要画什么或只改变什么
Input images: 按实际引用顺序逐张标明角色（无图片则省略）
Subject / scene: 主体及场景
Style / medium: 刮刀厚涂油画；按基线选择适当的笔触与肌理
Composition: 取景、视觉焦点、必要留白
Lighting / mood: 明暗层次、冷暖关系与情绪
Color palette: 用户给出的颜色、各自作用、容许范围
Materials / textures: 厚颜料刀面、断续刮痕、选择性露底
Invariants: 编辑时必须保留的身份、机位、几何、数量等
Constraints: 透明需求、文字处理、用户指定排除项
```

使用最贴合请求的单一 `Use case`，无需照搬所有栏目。复杂内容可中文或英文描述；用户要求的文字保持原文。默认不额外生成文字、签名、logo 或水印，但不能因此删去用户明确要求的内容。

按用途调整：背景先保证空间、焦点和必要 UI 留白；角色保证身份与轮廓；独立道具保证边缘和足够边距；UI 材质保证可读性及可拆分。厚涂强度在细小资产上应降低，不能把细节完全糊掉。比例和尺寸是目标，工具返回后核实实际值；不承诺未验证的精确尺寸或无缝拼接。

游戏界面默认把正式文字、按钮逻辑、交互状态留给引擎。用户只要图像资源时只交付资源，不擅自修改场景或代码。明确要求在 Godot 接入时优先预置节点。

## 3. 调用内置 image_gen

使用宿主提供的内置 `image_gen`（工具名可能显示为 `image_gen__imagegen`）。普通生图无需 API key，不为了更换保存路径、批量或指定尺寸转用 CLI。

- 新图且无任何参考图：只传提示词，省略图像引用字段。
- 有参考/编辑图且每张都有本地路径：先检查，再用当前 schema 支持的 `referenced_image_paths` 引用完整所需图集，并在提示词说明角色。
- 至少一张所需图只有会话图像：用 `num_last_images_to_include`，选择覆盖全部所需图像的最小近期数量，最多 5 张；两种引用字段不得同时传。
- 混合本地与会话图时，先显示本地图使所需图片都在可引用的近期范围。若单一引用机制无法覆盖完整图集，请求重新附图或请用户选择必要参考；不要悄悄丢图。对无本地路径的补图请求用正常聊天提出。
- 传入顺序必须与提示词里的 Image 1、Image 2 等一致。不在提示词中虚构工具没有实际收到的图。
- 多个不同资源分别调用，不默认把所有资产合成一张拼贴图。除非用户要求，单次需求先生成一张。
- 透明道具请求真实透明背景，保留 alpha；不默认绿幕或把棋盘格当透明。

宿主通过 `functions.exec` 编排时，遵循图像工具的等待与返回契约：初次请求使用 `// @exec: {"yield_time_ms": 120000}`；工具返回后用 `generatedImage(result)` 展示，勿打印完整 base64。仅在 exec 明确返回运行中的 cell 后使用对应 wait；实际调用参数和宿主当前说明优先。

如果工具缺失或失败，诚实报告没有生成图片并保留可执行提示词。若环境提供 CLI/API 备选，只在用户明确选择后按其 imagegen 流程运行，不自行安装 SDK 或偷偷转换付费服务。不要把提示词文本冒充完成的图像。

## 4. 检查与交付

检查生成图：主体是否符合请求；厚颜料是否有方向和层次而非均匀噪点；用户配色是否起主导作用；构图/身份保留项是否明显漂移；有无意外文字、物件或边缘缺损。编辑不能承诺逐像素不变。

一次明显失败可进行一次有针对性的修订，重复声明保留项；仍不合格则展示问题、说明限制并等待取舍，不无限自动生图。用户明确规定次数时以其为准。

预览/探索图直接内嵌展示，可留在工具返回位置。用户指定目标目录时将选定输出复制到那里；面向项目的正式资源须复制进项目（未指定位置时沿用现有资产目录，或用项目的 `output/imagegen/`），并使用不覆盖旧版的文件名。不要猜测输出文件路径，也不为复制图片擅自改动项目代码。

最终交付图片、实际保存路径（若有）、简短风格/配色说明以及最终提示词或提示词文件链接；说明使用内置工具或用户选定的备选。只有实际核验后才报告尺寸/透明通道。严格色值、像素级几何保持和跨图身份一致性需要额外验证，不说成已保证。
