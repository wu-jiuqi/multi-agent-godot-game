# 游戏 Agent 工作区规则

## 适用范围

本文件适用于当前 `game-production-pipeline` 插件内的所有 Agent、Skill、工作流、契约、脚本和测试。

## 设计约束

- 不把 P0～P9 的每个生产阶段机械地各做成一个 Agent；先判断它应是角色、Skill、工作流步骤还是共享契约。
- 每个 Agent 必须定义职责、非职责、允许自主决定的事项、必须请求人工判断的事项和文件所有权。
- 每个工作流节点必须定义准入条件、输入、输出、自动验证、人工验收、退出条件和失败回退路径。
- 结构化产物使用稳定 ID，并通过中心依赖清单追踪上下游影响。
- 人类负责项目方向、范围取舍、趣味性、情绪体验和最终验收；自动化负责生成、检查、执行和整理证据。
- 从代表性的垂直切片任务验证流程；未经真实任务重复验证，不把草案标记为稳定。
- Godot 项目优先使用编辑器内预置节点和场景结构；只有必须或明显优于预置方案时才通过脚本动态生成节点。
- 插件目录只保存通用框架；具体游戏的事实、设计答案、项目 Agent Preset、项目 Skill、审批与运行状态必须保存到目标项目实例。
- 任何持久部门、岗位、Agent Preset 或 Skill Binding 只有在人工审批记录与对象摘要一致后才能应用或生成 Codex Agent TOML。

## Skill 约束

- Skill 名称只使用小写字母、数字和连字符。
- 每个 Skill 必须包含 `SKILL.md`，只在需要时增加 `scripts/`、`references/`、`assets/` 和 `agents/openai.yaml`。
- `SKILL.md` 保持精简；详细资料与长示例放入 `references/`。
- 新建 Skill 使用官方初始化脚本，并在提交前执行快速验证。
