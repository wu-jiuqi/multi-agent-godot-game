# v0.3.0-alpha.1 测试手册

本手册区分“发布前包验证”和“发布后真实项目前向测试”。发布前不得修改 The Nameless Vessel。

## A. 仓库与插件包验证

在仓库根目录执行：

```powershell
python -m unittest discover -s game/game-production-pipeline/tests -p 'test_*.py' -v
python C:\Users\<user>\.codex\skills\.system\plugin-creator\scripts\validate_plugin.py game\game-production-pipeline
```

再对五个 `game/game-production-pipeline/skills/*` 目录分别执行 `quick_validate.py`。预期：51 项测试、插件清单和五个 Skill 全部通过。

## B. 隔离项目初始化

创建一个全新临时 Git 目录，不使用任何真实游戏项目。运行：

```powershell
python scripts/bootstrap_game_pipeline.py `
  --project-root <temp-project> `
  --project-id smoke-game `
  --project-name "Smoke Game" `
  --engine Godot
```

检查：

- 命令只输出计划，尚未出现 `game-pipeline/`；
- 计划列出所有文件动作、冲突、`created_at` 和 `approval_digest`；
- 使用错误摘要执行 `--apply` 必须失败且不写入；
- 使用相同 `created_at` 和正确摘要后才创建项目实例；
- 再次运行相同计划应全部为 `unchanged`；
- 用户原有 `AGENTS.md` 和 `.gitignore` 内容保持不变，只追加带摘要的托管区块。

应用后运行：

```powershell
python scripts/validate_project_instance.py --project-root <temp-project>
python scripts/plan_plugin_migration.py --project-root <temp-project>
```

预期：项目状态为 `normal`，迁移结果为 `no_change`。

## C. Agent Preset 审批链

1. 从 `assets/project-agent-preset.template.md` 创建一个 `pending` 项目 Preset；
2. 运行 `generate_codex_agents.py` 计划，确认 pending Preset 可见但不会生成 TOML；
3. 创建与 Preset 摘要一致的 Skill Binding 和人工审批记录，再标记 `approved`；
4. 执行生成器 `--apply`，确认 `.codex/agents/<slug>.toml` 可解析；
5. 修改 Preset、Skill 内容或审批摘要，确认生成器拒绝继续；
6. 在同名 TOML 放置一个无托管标记的用户文件，确认生成器不覆盖。

## D. Personal Marketplace

确认以下位置存在：

- `~/.agents/plugins/marketplace.json`
- `~/plugins/game-production-pipeline/.codex-plugin/plugin.json`

在 Codex 客户端的个人 Marketplace 安装或启用 `game-production-pipeline`，然后新建任务。当前任务不会热刷新插件能力。

在新任务中验证这五个名称可发现：

- `$bootstrap-game-pipeline`
- `$design-game-organization`
- `$operate-game-production-loop`
- `$review-game-gates`
- `$adapt-godot-production`

只要求 `$bootstrap-game-pipeline` 对临时项目生成计划，不应用到真实项目。

## E. 发布后真实项目测试

发布完成后，才在 The Nameless Vessel 开始前向测试。第一步只运行 bootstrap dry-run 并审阅影响清单；未确认精确摘要前不得写入。后续每个长期 Agent、部门、岗位和 Skill Binding 都要逐步讨论、形成 Change Set、显示组织图并由项目所有者批准。

真实样本验收目标：项目分析、首个专属编制、Contract 绑定、Godot 灰盒、独立 QA、人工门禁、失败退回和中断恢复能够形成可重放闭环。
