# v0.5.0-alpha.13 — 产品发现、组织注册与 Penpot 浏览器桥接

## 版本定位

本版在 `v0.5.0-alpha.12` 的六部门组织、产品原型和 Penpot-first 管线基础上，补齐无文档项目的产品发现入口、组织注册请求边界，以及本地项目与 dot 云端浏览器之间的 Penpot 文件桥接契约。它仍是 Alpha 预发布版本，不是 Production Ready；真实 Penpot 连接、视觉质量和目标 Godot 项目构建仍需独立验收。

## 本版变更

- 新增 `$product-discovery` Skill 与工作流：在缺少 brief/GDD/PRD/slogan 时先盘点事实、分轮提问，生成带 `confirmed/preference/hypothesis/unknown` 状态的初始 brief、PRD、问题和 handoff 提案，不把空模板或生成文案当成方向决定。
- 新增组织注册请求契约、样例和校验器。产品经理只能提交请求，AGT-ORG 只能生成绑定当前基线的 Change Set，人类批准后仍需独立 `core.change_set_applied` Event 才能写入 Registry。
- 新增 Penpot 浏览器文件桥接契约、样例规则和校验器，覆盖 request/ack/result 状态链、摘要、连接证据、稳定 ID、失败路由和重试边界；本地校验器不打开浏览器、不登录 Penpot，也不伪造远程成功。
- 扩展产品经理、组织、美术和 UI 交接文档与测试，修正刮刀厚涂画风注册表的目录摘要，并增加 alpha12→alpha13 的 metadata-only 显式迁移入口。

## 验收边界

插件单元测试、契约校验、编码校验、迁移回放和 synthetic 故障场景应通过。自动验证只证明文件结构、摘要链和失败路由自洽；它不能代替人类的产品方向/组织审批、Penpot 真实页面与组件评审、浏览器权限核对或 Godot 目标构建验收。无 Penpot 连接实例时，真实交付必须保持 `blocked`，不能把 synthetic 通过解释为远程成功。

## 迁移

已发布的 `v0.5.0-alpha.12` 项目可在隔离副本执行 `0.5.0-alpha.12 → 0.5.0-alpha.13` 的显式 metadata-only dry-run。迁移只更新受托管的 `AGENTS.md`、`plugin-lock.yaml`、必要的托管 Adapter/绑定摘要，并保留项目场景、资源、UI、Event History 和业务事实；未知 framework digest、非托管文件、损坏 managed block 或计划后漂移都必须 fail closed。不要手工改写 `plugin-lock.yaml` 或 managed block 绕过审批。

## 安装

插件与独立 UI Skill 分开安装；插件 ZIP 不会自动安装独立 Skill。更新 Personal Marketplace 源后执行：

```powershell
codex plugin add game-production-pipeline@personal
codex plugin list
```

确认版本为 `0.5.0-alpha.13` 且状态为 `installed, enabled`。独立 Skill 解包到 `C:\Users\30114\.codex\skills\ui-ux-pro-max`，再回读 `SKILL.md` 与 `references/penpot-handoff.md`。重装后需新建 Codex 会话才能加载新版 Skill。Windows PowerShell 5.1 读取中文文件时使用 `Get-Content -LiteralPath "文件路径" -Encoding UTF8`；执行 `chcp 65001`，并使用 PowerShell 7 复核。
