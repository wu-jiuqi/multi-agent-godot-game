# v0.5.0-alpha.12

## 主题

把“六部门框架 + 按需激活”落成可验证的协作架构：项目经理可以通过 P2P 咨询调用部门经理，统一整理 PRD/GDD 并交给人类审批；产品经理承担产品身份和 Penpot 原型交接；组织、咨询和原型链路均提供确定性校验与受控故障验证。

## 本版变更

- 增加六个固定但惰性的部门能力槽位：策划、美术、程序、音频、测试、工具。槽位目录不会自动物化 Department、Position 或 Agent Instance，项目仍需通过 Change Set 和人工批准激活。
- 增加部门经理作为部门管理层；项目经理可向部门经理发起结构化 P2P 咨询，咨询事件具备参与者、直接 peer 链、序列、摘要、SHA-256 链和幂等重放约束。
- 增加咨询事件实例校验器和有效/无效样例，明确它只验证事件声明与确定性重放，不冒充 Registry、宿主权限或真实模型审计。
- 增加产品经理的产品资料/身份/Prototype Intent Skill，以及 Penpot 原型编排 Skill；产品原型交接契约校验真实项目实例、Tool Registry、读前/读后证据、Screen/Flow 映射和外部人类审批记录。
- 增加组织/原型 synthetic 沙盒，覆盖未激活槽位、跨域 QA 写入、Penpot 超时回读、断连只读和重复同步稳定 ID；报告会明确 synthetic 范围，不把沙盒结果升级为真实交付。
- 新增 alpha.11 到 alpha.12 的受摘要保护迁移，并保留已支持历史版本到 alpha.12 的直接显式迁移入口。迁移只更新受托管元数据、绑定、Adapter 和 plugin lock，不改写项目已有场景、资源、UI、Event History 或业务事实。

## 验收边界

本版已通过插件回归、实例校验、确定性重放和 synthetic 故障用例。V3 真实 Penpot 纵切片仍未完成：当前验证环境没有连接 Penpot MCP 实例，因此不能声称真实页面、组件、Flow、截图或远程写入已通过。V4 的真实 P2P 成本/质量对照也未运行。自动校验和 synthetic 沙盒不能代替人类审批、真实工具权限核对、专业视觉评审或目标项目构建验收。

## 迁移

alpha.11 项目必须先在隔离副本执行 dry-run，并确认锁定的 framework digest 属于迁移白名单：已发布 alpha.11 为 `748a68f2325dc832f02c2f76e8d6c7138574bcc7015607c40805d7b678df1a23`，本仓库 alpha.11 开发头为 `e7b6fa8a8422b73c7fbfd66d2f826ac08367540dccfbf2b4ca439ecfe3876e10`。未知摘要、缺少显式迁移器、非托管 Adapter、损坏 managed block 或计划后文件漂移都会 fail closed。迁移必须保留 managed block 和 `plugin-lock.yaml`，不能手工改锁文件绕过审批。

## 安装

插件与独立 UI Skill 分开安装；插件 ZIP 不会自动安装独立 Skill。独立 UI Skill 本版同步切换到 Penpot 交接规范。更新 Personal Marketplace 源后执行：

```powershell
codex plugin add game-production-pipeline@personal
codex plugin list
```

确认版本为 `0.5.0-alpha.12` 且状态为 `installed, enabled`。独立 Skill 解包到 `C:\Users\30114\.codex\skills\ui-ux-pro-max`，再回读 `SKILL.md` 与 `references/penpot-handoff.md`。重装后需新建 Codex 会话才能加载新版 Skill。Windows PowerShell 5.1 读取中文文件时使用 `Get-Content -LiteralPath "文件路径" -Encoding UTF8`；执行 `chcp 65001`，并使用 PowerShell 7 复核。
